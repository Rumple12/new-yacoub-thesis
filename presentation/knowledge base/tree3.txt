* A JSON temperature event is sent to the n8n webhook, for example value 24.5.
* n8n reads the value from the request body.
* The deterministic workflow checks the rule:
-
if temperature >= 30.0:
    fan_on
else:
    fan_off
-
* Because 24.5 is lower than 30.0, n8n chooses the fan_off path.
* n8n sends an HTTP request to the middleware:
  middleware/api/routes.py -> POST /fan/off
* In middleware/api/routes.py, the POST /fan/off route is matched.
-
* That route calls the Python function:
  middleware/gpio/mock_sensor.py -> fan_off(reason="manual_api_call")
* fan_off() changes the internal simulated fan state in middleware/gpio/mock_sensor.py to:
  fan = off'
* _state = {
    "fan": "off"
}
-
* The middleware sends a JSON response back saying the action worked.



what to learn
-
1. n8n = workflow brain
2. Docker = how n8n is run locally
3. Python middleware = action side / middleman
4. JSON contracts = expected message structure
5. deterministic workflow = simple threshold baseline
6. agent-enhanced workflow = LLM produces structured action
7. CSV = recorded evidence
8. Raspberry Pi = validates action endpoint over network
9. limitations = small cases, simulated fan, single-run latency, safety design not runtime enforcement
10. contribution = measured architecture around the action
